# Training-Free Methods to Improve Machine Translation for the WMT 2026 Video Subtitle Translation Task

## TL;DR
- **Your highest-leverage move is a single fixed inference-time pipeline: context-aware windowed prompting with the provided metadata → generate N diverse candidates (Hunyuan-MT-7B + one contrast model) → fuse/rerank with Hunyuan-MT-Chimera or CometKiwi → one LLM proofread/post-edit pass with an auto-built episode glossary.** Every stage adds neural-metric gains that stack and none require training: Chimera-style fusion adds ~+2.3% XCOMET-XXL on average (up to +5.6% on XX→XX); QE reranking/fusion adds ~+0.4 to +5.5 COMET/XCOMET points; context injection and post-editing each add ~+0.5–2 COMET.
- **A rules check changes everything: WMT 2026 Video Subtitle Translation is a CONSTRAINED TRACK ONLY** — the final system must be **< 20B parameters** and you must **open-source the weights** under a permissive (Apache/MIT-style) license. So GPT-4o/Claude/Gemini cannot be in the submitted system; build the whole pipeline from open ≤20B models (Hunyuan-MT-7B / Hy-MT2-7B / Qwen2.5 + CometKiwi as scorer). The task offers zh→en, zh→th, zh→id, zh→ms, zh→zh-TW; **Chinese→Indonesian is officially included.**
- **For zh→id (low-resource), prefer direct translation with strong few-shot examples over English pivoting, and guard against metric gaming:** QE-reranking gains in low-resource directions can be illusory because CometKiwi/XCOMET can be fooled by code-switching. Optimize with a metric family different from the one you expect to be judged on, hold out a dev set, add an off-target language filter, and human-spot-check.

## Key Findings

### The task setup (verified from the official page, last updated 2026-07-07)
- **Language pairs (Chinese Simplified source):** zh→English, zh→Thai, zh→Indonesian, zh→Malay, zh→Chinese Traditional (Taiwan). Your two directions (zh→en, zh→id) are both official.
- **Track:** Constrained only. Any data/models/frameworks are allowed **provided you release the model weights** under a license permitting at least unrestricted non-commercial use. **Final model total parameters must be < 20B** (MoE counts full parameter count; **ensembles count the SUM of their weights**). Weights must be released with the submission.
- **Recommended base model:** organizers explicitly recommend `tencent/Hy-MT2-7B` and offer **monetary prizes** for competitive systems built on Hunyuan-MT. Organizers: Tencent Hunyuan + Tencent Video.
- **Data & metadata:** test data = recent video subtitles with high-quality human references. Each sample includes subtitle source text plus **metadata: video description/synopsis** (the page also references character lists, domain info, and glossaries as leverageable metadata). Videos are viewable on wetv.vip and v.qq.com. Metadata use is optional but encouraged, "especially for domain-specific terminology and character names." **No video frames or audio are distributed as core input — only text + textual metadata**, so treat true multimodal (frame/audio) exploitation as out of scope for the official pipeline.
- **Submission:** SRT files named `vid_langshort.srt`, emailed to wmt26_subtitle@163.com; **one submission per team**; a system description paper is required; models must be open-sourced (include the link).
- **Evaluation:** both automatic metrics and human evaluation; detailed protocol "announced with the test data." Given the organizers are the Hunyuan-MT team — whose RL reward is "a composite reward function integrating quality-aware (XCOMET-XXL, DeepSeek-V3-0324), terminology-aware (word alignment), and repetition penalty signals," and whose auto-eval uses **XCOMET-XXL and CometKiwi** — plus WMT norms, expect **XCOMET-XXL, CometKiwi, and likely a GPT/LLM-based (GEMBA-style) evaluation**, with chrF/BLEU secondary.
- **Timeline:** test data released 1 July 2026; **translation submission deadline 15 July 2026**; system paper + constrained-weights release TBA August 2026.

**Implication:** the ≤20B + weight-release constraint means the entire submitted system must be open-weight. A compliant pipeline is: Hunyuan-MT-7B (or Hy-MT2-7B) translator + a second small open model as a contrast candidate generator + CometKiwi (0.5B–3B, XLM-R based) reranker + an open 7B post-editor. To respect the "ensembles count the sum of their weights" rule, keep to roughly two 7B models + the QE model (≈14–17B total).

### The user's current approach (repo + baseline)
The repo (github.com/pieter-undergraduate-thesis/wmt-2026-video-subtitle) could not be fetched programmatically — GitHub blocks automated access and it may be sparse or private; re-verify manually. Per the task brief, the current baseline is **zero-shot, single-pass, sentence-by-sentence translation with Hunyuan-MT**, using the model card's default prompt (*"Translate the following segment into <target_language>, without additional explanation.\n\n<source_text>"*) and recommended decoding (top_k=20, top_p=0.6, temperature=0.7, repetition_penalty=1.05; note there is no default system prompt). This leaves large, well-documented headroom: it ignores (a) inter-subtitle context, (b) the provided synopsis/character-list metadata, (c) test-time candidate generation + reranking (the exact mechanism behind the model's own SOTA Chimera variant), and (d) episode-level terminology consistency.

### How Hunyuan-MT-Chimera works (and why you should reuse it)
Hunyuan-MT-Chimera-7B is a **weak-to-strong fusion** model: the base Hunyuan-MT-7B generates multiple (≈6) candidate translations under varying decoding settings, then Chimera "analyzes the following multiple <target language> translations… and generates a single refined <target language> translation." Its fusion prompt is public and reusable verbatim. Per the Hunyuan-MT Technical Report (arXiv 2509.05209), Chimera **achieves an average gain of 2.3% in XCOMET-XXL across all directions on Flores-200, with the most pronounced improvements on ZH→XX (+2.5%) and XX→XX (+5.6%)** — concretely, Chimera-7B XCOMET-XXL is **0.8974 on ZH→XX vs 0.8758 base**, and **0.8268 on XX→XX vs 0.7829 base**. The base Hunyuan-MT-7B itself scores **0.8585 XCOMET-XXL on WMT24pp, outperforming Gemini-2.5-Pro (0.8250) and Claude-Sonnet-4 (0.8120)**, and ranked first in 30 of 31 WMT2025 language pairs. Chimera is open-weight and 7B, so **using it directly as the fusion stage is the single most on-brand, lowest-effort win** and fits the parameter budget.

### Taxonomy of training-free techniques with evidence of COMET gains

**1. Test-time candidate generation + QE reranking / MBR (strongest evidence; directly targets the metrics).**
- Best-of-N with QE selection (CometKiwi) is "quality-aware decoding" (Fernandes et al. 2022). Tan et al. 2025 ("Investigating Test-Time Scaling with Reranking for MT," arXiv 2509.19020) report for **WMT24 en→zh, Qwen2.5-7B zero-shot: XCOMET rises 73.62 (N=1) → 77.00 (N=8) → 79.12 (N=1024)** — about **+3.4 XCOMET at N=8, +5.5 at N=1024**; the 3B model gains **+6.76** at large N. Small models with large N can match a 72B model at N=1. BLEU barely moves — gains concentrate in neural metrics, exactly what this task rewards.
- **MBR with COMET utility** (Freitag et al. 2022, "High Quality Rather than High Model Probability") yields large jumps, e.g. en→de COMET 77.3 (beam) → 83.9 (MBR-COMET); the MBRS library (Deguchi et al. 2024) confirms consistent gains across en↔{de,zh,ja}.
- **QE-fusion** (Vernikos & Popescu-Belis 2024, "Don't Rank, Combine!," arXiv 2401.06688) combines spans from multiple candidates via CometKiwi and **consistently beats beam, MBR, and QE-reranking**. QE-reranking over beam: en→de Llama2-7B COMET 81.76→82.73 (+0.97), en→ru +0.90; NLLB-1.3B en→de +0.38. QE-fusion on XGLM en→de adds ~+4 COMET / +3 BLEURT over the ICL baseline.
- **WMT24/25 top systems use exactly this.** Unbabel Tower-v2 (WMT24 winner in 8 pairs) used MBR + "Tuned Reranking" with a COMET22 objective and COMETKIWI-XL / XCOMET-QE-XL; HW-TSC used MBR over NMT+LLM hypotheses (COMET 0.6928→0.7178→0.7234); EuroLLM's WMT25 submission moved CometKiwi 0.6843→0.7033 via reranking. This is the mainstream recipe.

**2. Document-level / context-aware prompting (no training).**
- Feeding previous N subtitle lines (or a whole scene) as context improves coherence, anaphora resolution, and speaker/register consistency. Doc-level MT work shows in-context ("Doc2Doc") beats isolated sentences on document-level COMET (d-COMET, Vernikos et al. 2022). Multi-Knowledge Fusion (Liu et al. 2025, arXiv 2503.12152) adds **+0.4 to +0.8 COMET** by injecting a document summary + entity translations — directly usable with the task's synopsis + character-list metadata.
- Practically: translate in sliding windows (e.g. ~15 lines with 5–10 lines of prior context), preserving SRT structure and sending only dialogue text.

**3. LLM post-editing / self-refinement (no training).**
- Automatic post-editing with a strong LLM (Raunak et al. 2023, GPT-4 APE) improves COMET across pairs, especially into English. Chen et al. 2023 iterative refinement raises COMET while lowering BLEU/chrF (it reduces "translationese"). TEaR (Feng et al. 2024) — Translate, Estimate, Refine — improves semantic metrics like COMET more than n-gram metrics. Andrew Ng's translation-agent reflection workflow is the practical template. Reflective refinement gains are "stronger and more consistent in COMET than BLEU."
- Multi-agent (Translator→Proofreader→Editor) is validated for subtitles by **ViDove** (Lu et al. 2025, arXiv 2507.07306, EMNLP 2025 Demo), which is entirely training-free at inference ("neither the baseline models nor ViDove undergo any additional fine-tuning"). Its five modules are vision agent, auditory agent, translation agent (Translator + Proofreader + Editor), multi-agent post-editing, and a long/short-term memory system. On its **DoveBench** benchmark (50 videos, 17.23 hours, 16,968 subtitle entries; metrics BLEU/BLEURT/SubER/SubSONAR/sCOMET) it reports **~+28% BLEU and ~+15% SubER over the previous SOTA baseline**; ablations show **removing the Proofreader agent causes the largest quality drop** ("its importance for corrections and consistency"), while vision has limited effect on BLEU/BLEURT but helps entity-level name/object correctness. (ViDove uses GPT-4o/Gemini; for a compliant submission replace these with open 7B models.)

**4. Terminology / glossary enforcement (no training) — critical for xianxia/wuxia dramas.**
- Two-pass approach: first pass extracts named entities (character names, sects, titles, cultivation realms, fantasy items) from the whole episode/synopsis and builds an episode glossary with a single agreed rendering each; second pass translates with only the relevant terms injected per window (don't dump the whole glossary). Translate-and-Revise (Zhao et al. 2024, arXiv 2407.13164) shows natural-language constraint prompts raise entity/terminology consistency (CCR) by up to ~19–24% and add ~+0.9 BLEU on entity translation. Genre practice for Chinese web-novel translation confirms consistent handling of chengyu and cultivation terms is the dominant quality lever for this genre.

**5. Few-shot in-context example selection (no training) — especially valuable for zh→id.**
- Retrieve similar source sentences/subtitle pairs from a parallel pool as few-shot demonstrations. Nzeyimana 2024 (arXiv 2408.00397) shows **similarity-based selection gives large gains in low-resource directions (up to ~10 COMET into Swahili/Wolof)** while gains are modest for high-resource. CTQScorer (Kumar et al. 2023) finds COMET-QE is a better selector than LaBSE. Use ~5 shots (more can hurt); edit-distance ("fuzzy") retrieval is a strong, cheap baseline that can bring a generic open model close to GPT-4o-mini quality.
- **Retrieval pool for zh→id:** the OPUS OpenSubtitles corpus (Lison & Tiedemann, LREC 2016; refreshed as Helsinki-NLP/OpenSubtitles2024) covers both Chinese (Simplified `zh_CN`) and Indonesian (`id`) — the ideal in-domain pool (the base corpus spans ~1,689 bitexts / billions of sentences across 60 languages). Also CCMatrix/NLLB for volume and NusaX for Indonesian generally. Build a FAISS index over source-sentence embeddings and retrieve top-k in-domain subtitle pairs per line. Index zh–en subtitle pairs too, for consistency.

**6. Retrieval-augmented / kNN-MT.** kNN-MT is training-free at inference but needs a datastore of NMT decoder hidden states — heavy engineering for marginal benefit here. **Few-shot retrieval prompting achieves most of the benefit with far less effort; deprioritize kNN-MT.**

### Subtitle-specific considerations
- WMT26 emphasizes length/timing constraints and register and requires SRT output, but the **evaluation appears translation-quality-focused (COMET-family + human), not a formal reading-speed/CPL compliance score** like IWSLT's subtitling track (which scores CPS ≤ 21 chars/sec, CPL, TER-br). Still, keep translations concise — overly long lines hurt chrF and readability. A light length hint works: isometric-MT work (Anastasopoulos et al. 2022; arXiv 2506.04855) shows prompt-based length control is effective but must be paired with short demonstrations.
- Preserve SRT indices/timecodes locally; send only dialogue text to the model. Community tooling (rockbenben/subtitle-translator) confirms models <70B can misalign timecodes if fed raw — never let the model touch timing.
- **Multimodal:** the task ships no frames/audio, so VLM scene-description is not part of the official input. If you fetched source videos yourself, a training-free VLM caption could disambiguate speaker gender for pronoun/register choice — but this is high-effort and legally grey. The synopsis + character list gives most of that benefit textually; use textual metadata, not video.

### Chinese→Indonesian specifics (the important low-resource direction)
- **Direct vs pivot:** evidence is mixed and system-dependent. Pivoting through English helps when the direct pair is essentially zero-resource or the direct model is weak, but with a strong direct multilingual model **direct beats pivot** (pivoting compounds errors and loses register/pragmatics). Hunyuan-MT supports Indonesian directly and is strong on ZH→XX, so **default to direct zh→id**; optionally add one English-pivot candidate (zh→en→id) as an *extra* candidate into the reranker rather than the primary path — capturing pivot's occasional benefit without its risk.
- **Register/formality is the #1 zh→id quality lever.** Indonesian is diglossic: formal *bahasa baku* (Anda, full affixation) vs colloquial *bahasa gaul* (kamu/kau, and Jakarta-slang gue/lu). TV-drama dialogue subtitles generally want **colloquial-but-clean Indonesian**: kamu/aku among peers, Anda/Bapak/Ibu for deference — matched to the on-screen social relationships. Put an explicit register instruction in the prompt keyed to the character list ("informal kamu/aku between friends; Anda or titles Bapak/Ibu for elders/superiors"). Handle inclusive vs exclusive "we" (kita vs kami) and capitalize "Anda."
- **Fantasy terminology:** fix a loanword convention (transliterate sect/title names consistently; gloss cultivation terms once) and enforce via the episode glossary — same mechanism as for English.
- **Metric caution:** Tan et al. 2025 explicitly warn that in low-resource pairs, QE/neural metrics "are misled by severe code-switching texts" — a candidate slipping in Chinese characters or wrong-language tokens can still score high on CometKiwi. For zh→id, add a language-ID filter to drop off-target candidates before reranking, and validate with chrF + manual spot-checks.

### Risks / caveats
- **Metric gaming (optimize-for vs judged-by mismatch):** if you rerank/fuse with CometKiwi but organizers score with XCOMET-XXL and a GEMBA-style LLM judge, you can overfit CometKiwi's blind spots. Mitigation: rerank with a *different* metric family than you expect to be judged on (or MBR with XCOMET-QE utility), and always keep a reference-based dev check on a held-out slice of the demo data.
- **MBR/QE overfitting to the utility metric** ("Chasing COMET," Jon et al. 2024): iterating too hard degrades true quality even as the utility metric climbs. Stop after one refinement pass; cap N (diminishing returns after N≈8–16 in the TTS study).
- **Length/format:** post-editing/refinement tends to lengthen or paraphrase, lowering chrF/BLEU even as COMET rises — acceptable here since neural metrics dominate, but monitor the length ratio.
- **Compute:** N-candidate generation + neural scoring is O(N) forward passes plus O(N) (QE) or O(N²) (MBR) metric calls. On lab GPUs with vLLM this is very feasible for a 7B model at N=5–8; MBR with COMET at large N is the costly part — use `comet-mbr --rerank_top_k` to prune, or prefer QE-reranking/QE-fusion (O(N)).

## Details: the recommended pipeline (all open-weight, <20B, no training)

**Stage 0 — Preprocess.** Parse SRT; keep timecodes/indices out of the model. Group lines into sliding windows (~15 lines + 5–10 lines prior context). Parse metadata: synopsis, character list, any provided glossary.

**Stage 1 — Episode glossary (first pass).** Run Hunyuan-MT-7B (or Qwen2.5-7B/14B) once over the episode + synopsis to extract named entities (characters, sects, titles, fantasy items, recurring idioms/chengyu) and fix one target rendering each per direction; seed from any provided glossary/character list.

**Stage 2 — Context-aware candidate generation.** For each window, prompt with: domain/style hint ("subtitle from a Chinese <genre> drama"), synopsis summary, relevant glossary terms, prior-line context, and (for id) a register instruction. Generate **N≈5–6 candidates**: mix (a) Hunyuan-MT-7B at varied temperature (the Chimera recipe), (b) one contrast open model (Qwen2.5-14B-Instruct or Hy-MT2-7B), and optionally (c) one English-pivot candidate for zh→id.

**Stage 3 — Fuse / rerank.** Either feed the N candidates to **Hunyuan-MT-Chimera-7B** (its native fusion prompt) — lowest effort, on-brand — or do **QE-fusion / QE-reranking with CometKiwi** (or MBR with a COMET-QE utility). Add a language-ID off-target filter for zh→id.

**Stage 4 — Post-edit (one pass).** A single LLM proofread/refine pass (TEaR/Proofreader-style) checking adequacy, register consistency, glossary compliance, and subtitle brevity. Do NOT iterate more than once.

**Stage 5 — Consistency + format check.** Enforce the glossary across the whole episode (verified find/replace); re-attach timecodes; emit `vid_langshort.srt`.

## Recommendations (prioritized, with effort / compute / expected gain)

1. **Lock compliance first (½ day, no compute).** Confirm every model in your final pipeline is open-weight and total params <20B; plan the weight release. Remove any GPT-4o/Claude/Gemini from the *submitted* system. This is a hard gate — a non-compliant system is disqualified regardless of quality.
2. **Add Hunyuan-MT-Chimera fusion over N candidates (1–2 days, moderate compute, ≈+2–5% XCOMET).** Highest ROI: it's the model's own SOTA mechanism, open-weight, and matches the metric. Generate ~6 candidates with Hunyuan-MT-7B at varied decoding; fuse with Chimera. Benchmark on demo data.
3. **Add context-aware windowed prompting + metadata injection (1–2 days, low compute, ≈+0.5–1 COMET; larger for coherence/anaphora).** Uses synopsis + character list; explicitly encouraged by organizers and cheap.
4. **Build and enforce an episode glossary (2–3 days, low compute; large qualitative gain for xianxia/wuxia and zh→id consistency).** Biggest lever for the fantasy-drama domain where names/sects/titles recur.
5. **Add similarity-based few-shot examples, especially for zh→id (2–3 days, moderate; up to several COMET points in low-resource).** Index OpenSubtitles zh–id; retrieve top-5 per line. Also index zh–en pairs.
6. **Add a single LLM post-edit pass with register/brevity checks (1 day, low compute, ≈+0.5–1 COMET, reduces translationese).** Keep to one iteration.
7. **Swap the reranker metric to avoid gaming (½ day).** If you expect XCOMET/GEMBA judging, rerank with a different QE model (or MBR with XCOMET-QE) and validate on a reference-based dev set.

**Benchmarks/thresholds that change the plan:**
- If Chimera fusion gives <0.5 XCOMET gain on your dev set, your candidates aren't diverse enough — widen the temperature spread or add a second base model.
- If zh→id CometKiwi rises but chrF collapses or off-target rate is high, you're gaming the metric — tighten the language filter and trust chrF + manual checks.
- If N>8 shows no dev gain, cap N at 8 to save compute.
- If post-editing lowers dev COMET, disable it (over-refinement).

## Caveats
- The repo could not be programmatically inspected; the analysis assumes the stated baseline (zero-shot single-pass Hunyuan-MT). Re-verify against the actual code.
- The exact WMT26 evaluation metrics/human protocol were unpublished at research time ("announced with the test data"); the metric assumptions (XCOMET-XXL/CometKiwi/GEMBA) are inferred from the organizers' identity (the Hunyuan-MT team, whose reward and eval use XCOMET-XXL and CometKiwi) and WMT norms — confirm before over-optimizing to any single metric.
- Reported COMET/XCOMET gains are largely from other domains/pairs (news, Flores, general MT); subtitle-domain and zh→id gains may differ. Treat all numeric gains as ranges to validate on the demo/dev data, not guarantees.
- Low-resource (zh→id) neural-metric gains are the least trustworthy due to documented QE blind spots; human spot-checking is essential there.
